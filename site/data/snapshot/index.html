Genesis snapshot — and how to check it yourself

Eligibility was decided once, from the on-chain state at snapshot block B = 50,615,795 — the block in which the token was deployed. Everything needed to reproduce that decision is published here. You are not asked to trust it; you are asked to re-run it.

1. Check the set root

Recompute the Merkle root from the list and compare it with what the contract stores. If these differ, the published list is not the committed one.

python3 lottery/build_v2_proofs.py --addresses eligible.txt --out /tmp/check --limit 0
cast call 0x292198f6aceb505EbaD96ba7654bAe70B57c0fdd "setRoot()(bytes32)" \
  --rpc-url https://base-rpc.publicnode.com

2. Check the candidate universe

The header binds candidates_keccak = keccak256 of the candidate file's bytes.

gh release download snapshot-b50615795 -p candidates.txt.gz -R second-btc/second-bitcoin
gunzip -c candidates.txt.gz > candidates.txt
python3 -c "import sys;sys.path.insert(0,'lottery');from keccak import keccak256;\
print('0x'+keccak256(open('candidates.txt','rb').read()).hex())"   # == header.json candidates_keccak

You do not have to trust this file either: §2 of the eligibility spec defines the candidate set as the senders of the window's blocks, so it is re-derivable from any archive node.

3. Re-run the whole rule

The strongest check. This re-derives the block anchors from T_B, refuses a header whose parameters differ from the verifier's own constants, re-reads every consensus value from archive nodes with no derived shortcuts, and exits non-zero on any mismatch.

BASE_RPC_URL=<base archive> ETH_RPC_URL=<eth archive> \
python3 lottery/snapshot_v2.py verify \
    --header header.json --candidates candidates.txt \
    --expect-root 0x40586f19308707d4dd2f4db69416ad385f2d5b07ab7c616ae9aae1ac21c69390 \
    --expect-n 84089

What the rule was

All of, measured at B: held between 0.1 and 40 ETH (Base and Ethereum balances combined) at both B and two weeks before B · first transaction at least 12 months before B, taking the earlier of the two chains · between 20 and 20,000 lifetime transactions across both chains · sent a transaction within the last ~two weeks · a plain wallet (no contract code, or an EIP-7702 delegation only). Thresholds are in ETH, so no price source or oracle is involved. The token, pool, vesting and founder addresses are excluded and named in the header.
